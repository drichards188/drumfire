# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Drumfire: a three.js (WebGL2) heavy artillery game set in the Ypres salient, autumn 1917, built from the MaxGFX framework (`../threejs-maxgfx`) and the sibling game Echelon (`../threejs-iads`); both are separate projects and read only from here, do not edit them. The player commands a Heavy Artillery Group: a 15-inch howitzer, a section of two 9.2-inch howitzers, a battery of four 6-inch 26 cwt howitzers, a section of two 60-pounders and a 12-inch railway howitzer. Fire missions arrive from forward observers, aircraft, a kite balloon and sound rangers; the player lays the guns from the artillery board, ranges with the observers' reports, fires for effect, answers SOS rockets and, late in the game, lifts the creeping barrage at Zero hour. Left half of the screen: third-person 3D view of the selected unit; right half: its fire control console. Plain ES modules, no TypeScript, no framework; runtime dependencies are three.js and lil-gui only. Everything is procedural except four CC0 recordings in `public/audio` (`CREDITS.md`). `DESIGN.md` is the contract between the modules (conventions, data shapes, commands, events) with a changelog; keep it current when an interface changes.

**The simulation is an arcade-level game, not a gunnery simulator** (DESIGN.md, "Simulation fidelity"): shells fly a simple drag-and-gravity integration with game constants, range tables come from that same integrator, errors are a per-gun calibration error, a daily wind and random dispersion, and damage comes from a game table by calibre and target hardness. Period detail belongs in the look, the words and the procedure (yards, degrees and minutes, map squares, the RFC clock code), never in weapons-effects modelling. Spectacle wins when a choice is between subtle and spectacular, but dirt and smoke must move like dirt and smoke and sound travels at 343 m/s.

## Commands

```bash
npm install
npm run dev      # Vite dev server on http://localhost:5201 (--host, strictPort)
npm run build    # production bundle in dist/ (inputs: index, models, ui, audio, world, fx)
node tools/simtest.mjs 1 2 3 --both --quiet   # headless battles: all-auto vs a scripted player
node tools/simtest.mjs 1 2 3 --all --difficulty all --table   # + a scripted player with all five units
node tools/audiotest.mjs                       # renders every sound bank offline, reports levels, exits 1 on a failure
node tools/shot.mjs <path> <out.png> [--size WxH] [--wait ms] [--until expr] [--eval expr]   # headless capture
```

No tests, linter or formatter beyond those tools. `simtest.mjs` flags: `--both` (players `auto` and `player`), `--all` (`auto`, `player`, `full`), `--players a,b`, `--difficulty Easy|Normal|Hard|all` (default Normal), `--quiet`, `--table` (summary only), `--log` (radio log), `--jobs N` (worker threads); seeds are bare numbers (default 1 2 3). `player` is a scripted competent player on the 15-inch, the 9.2-inch and the 6-inch battery, `full` the same on all five units. Env vars for debugging: `MIS=1` lists missions, `OCC=1` piece occupancy, `ZDBG=1` Zero-hour groups, `DBG=<t> DBGU=<unit>` one unit's state.

`tools/shot.mjs` launches its own headless Chromium (SwiftShader WebGL2) from `~/.cache/ms-playwright` via `playwright-core`, prints console and page errors, blocks the Vite HMR socket so a save cannot reload the page mid-capture, and needs the dev server running on port 5201 (it is normally already up; do not start a second one). Do not use the Playwright MCP browser for this project. Put captures in `shots/` (gitignored). `window.__drumfire` exposes every system (`renderer scene camera terrain atmosphere post fx flares hud chase params frame clouds weather world craters sim audio panel rigs unitRoot units handlers renderLayer sun`) plus `select(i)`, `start()`, `setTimeScale`, `followShell`, `newestShell`, `sandboxBlast`, `sandboxBurst`, `events`, `hooks.<event>` (called after each sim event), `onFrame` (array of per-frame callbacks), `aim` (a `{x,y,z}` the camera looks at), `state`. `__drumfire.fastForward(seconds, { unit, scale, settle })` stops the loop, runs the battle without drawing at `scale` (default 8) and draws a few frames, so a capture can jump into a raid; note that `unit` there is the 0-based index handed to `select`, while `?unit=N` is the 1-based unit id. `frame(dt, draw)` steps one frame. Example: `node tools/shot.mjs "/?play=1&unit=1&quality=Low" shots/x.png --until "window.__drumfire?.state === 'playing'" --eval "window.__drumfire.fastForward(120, { unit: 0 })"`.

URL params on `/`: `?quality=Low|Medium|High|Ultra` (default Medium), `?play=1` (start at once), `?unit=N` (unit id 1 to 5), `?tutorial=<id>` (start a lesson), `?hour=H` (fixed time of day, e.g. 5.25; without it the sim's clock drives the sun), `?weather=Clear|Overcast|Drizzle|Rain|Mist` (default Overcast), `?sandbox=1` (no title screen, no sim battle: B fires a fake blast of the selected unit's calibre plus a fake shell that bursts 300 m ahead, N a burst 300 m ahead at once, K star shell, L Very light, J SOS rocket over the selected unit's front). `?tdbg=` is a terrain shader bisecting aid.

Dev pages (Vite serves all; the five root pages are also build inputs, the `src/` viewers are dev server only): `/models.html?kind=bl15|bl92|bl6|bl60|rail|crew` (model viewer; also `&all=guns|crew|outfits`, `&shell=<kind>`, `&target=<kind>`, `&pose=elevation:0.6,recoil:1,breech:1,traverse:0.2,crane:0,hoist:2,trolley:-2`, `&load=tray|crane|trolley`, `&crew=1`, `&anim=1`, `&cam=az,el,dist`, `&night=1`, `&ortho=right|left|front|rear|top` for orthographic blueprint views with a metre grid), `/ui.html?unit=ID&scn=ranging|sos|dead|night` (the console against `src/ui/mock.js`), `/audio.html` (audio smoke test, `window.__audioReport.ok`), `/world.html?at=...&cam=az,el,dist&hour=&weather=&craters=N&world=0&still=1` (terrain and dressing), `/fx.html` (effects sandbox; `&fx=`, `&sheet=t1,t2,..` contact sheet, `&night=1`, `&grade=`, `&ground=`, `&fuze=`), and the page-local viewers `/src/models/inf/preview.html` (`?side=british|german&blast=1&cam=az,el,dist&far=1&n=200&force=dead|down|throw`), `/src/render/preview.html` (`?unit=1&step=ram&t=0.5&cam=az,el,dist`, steps depress open shell ram cartridge close prime lay ready fire idle; `&run=1` runs the sim live; `window.__render.set(step, t)`), `/src/models/t/preview.html` (`?kind=bl6|bl60|german:fh15`, `?target=battery&dmg=0.5`, `?shell=all`) and `/src/world/preview.html` (`?at=&cam=&sun=&fog=&still=1`).

## Architecture

### Orchestration (`src/main.js`)

`init()` builds atmosphere, terrain, clouds, fx, flares and weather, then loads the optional modules (sim, panel, audio, guns, world, craters, render) with a tolerant `optional()` import so a broken module degrades instead of blocking. It creates the `Sim` (started in attract mode: a demonstration bombardment behind the title screen, nothing scored or destroyed), the gun rigs (`rigs`, keyed `${unitId}:${pieceIndex}`), the render layer (`createRender`), `patchSceneFog(scene)`, post, the chase camera, the `AudioEngine` and the `Panel`. Cross-system effects go through `sim.events` handlers wired in main (fire, shellBurst, enemyFire, incoming, secondary, flare, sos, lift, pieceHit, pieceDestroyed, targetDestroyed, report, mission, radio, phase, state); modules do not import each other's state. "Take command" calls `start()`, which runs `sim.newGame({ difficulty, attract: false, seed })`, `renderLayer.reset(sim)`, `panel.reset()` and `patchSceneFog(scene)`. Audio starts on the first pointer or key gesture.

Per frame (`frame(forcedDt, draw)`): sun and sky from the sim's clock (or `?hour=`), `sim.update(dt)` (dt is time-compressed by `params.timeScale`, steps 0.25 to 8 on `[` and `]`), `renderLayer.update(dt, rawDt, sim, fx, camera)`, `world.update`, `craters.update`, new shells handed to `audio.shell`, `__drumfire.onFrame` callbacks, camera (`chase.update`), the camouflage-net cutaway uniforms, terrain, atmosphere, clouds, fx, flares, weather, fog, post, `post.render`, then HUD clock, `panel.update`, ambience and `audio.update`, dynamic resolution, and the compass, target markers and mission bracket. `rawDt` drives cameras, post and audio. On the title screen `chase.cine(true)` drifts the camera, main cuts to the next unit about every 26 s and rides the shell of a gun that fires in the demonstration battle. F rides the selected unit's newest shell to its burst (`ChaseCamera.followShell(shell, { onBurst })`); F again, a unit key or C returns to the unit. With sound running, shake and dazzle arrive with the pressure wave (`audio.onShock`, after the 343 m/s delay); without audio, main shakes at the burst (`blastTrauma(calibre, d)`).

The `params` object is the single source of truth for settings (lil-gui behind the gear button); `QUALITY` presets (Low, Medium, High, Ultra) set pixel ratio, shadow map and extent, AO, ray and DOF samples, the fx budget and the smoke cap. Default grade is `Flanders`; `post.js` `GRADES` also holds Kodachrome, Natural, Cinematic, Warm, Cool, Vivid, Newsreel and 1917.

### World frame (`src/sector.js`)

Metres, y up, origin at the centre of the Group's gun line, north -Z, east +X (the Germans are to the east); a bearing b at range r is `x = r sin b, z = -r cos b` (`fromBearing`, `bearingOf`, `headingFor`). Model space: front -Z (the muzzle points -Z at zero traverse and elevation), ground at y = 0; headings are `rotation.y`. Traverse is `rotation.y` of the traverse pivot relative to the platform (+ = left), elevation `rotation.x` of the elevation pivot (+ = up), recoil `position.z` of the recoil pivot (+ = back). People see yards (`YARD = 0.9144`), degrees and minutes of arc (`MIN`) and map references; convert only at the display edge. `sector.js` is plain data and pure functions and holds `UNITS` (five units with their pieces), `LINES` (trench control points), `SECTORS` (A Frezenberg, B Zonnebeke road, C Polygon, D Gheluvelt, by z range, the SOS lines), `SITES` (batteries B1 to B4, pillboxes M1 to M4, dumps D1 D2, balloon K1, HQ H1, crossroads X1, railyard R1), `PLACES`, `GROUND`, `ZONE`, `RAIL_MAIN`, `RAIL_SPUR`, `piecePlacements`, `flatPads`, and the trench map grid. Read it; never hard-code positions elsewhere. Changes to `sector.js` go through the lead and are noted in the DESIGN.md changelog.

Grid references follow the British 1:20,000 system, sheet 28 (`SHEET`): 6000-yard lettered squares A to X (four rows of six), each cut into 36 numbered 1000-yard squares, each quartered a (NW), b (NE), c (SW), d (SE), and a point in a quarter given in tenths of easting then northing: `J.14.c.3.7` (`gridRef(x, z, precision)`, `fromGridRef(ref)`, `toGrid`, `fromGrid`; precision 2 gives `J.14.c.35.70`).

### Simulation (`src/sim/`, Node-safe)

`Sim` steps at a fixed 0.05 s (`STEP`, `update` splits long frames; `sim.alpha` is the render interpolation fraction). Files: `sim.js` (Sim, commands, shell stepping), `tables.js` (`GUNS`, `SHELLS`, `FUZE`, `TARGETS`, `FFE`, `DIFFICULTY`, `CLOCK_KEYS`, `PHASES`), `shells.js` (integrator, `rangeTable`, `solveElevation`, `autoCharge`), `guns.js` (units, pieces, orders, the loading cycle, the shot), `targets.js`, `observers.js` (reports), `enemy.js` (counter-battery fire, harassing fire, the hurricane, star shells), `infantry.js`, `crews.js` (AI), `director.js` (missions, phases, clock, barrage, win and loss), `flight.js`. Units, pieces, shells, targets, missions and infantry groups are plain objects the UI and render layer read directly; shapes and the command table (`mission lay correct charge fuze rounds fire cease mode sos`) are in DESIGN.md. Piece states: idle, loading, laying, ready, recoil, dead; the loading cycle is the step list in `GUNS[kind].load` and `piece.job = { step, t, dur, i, n }`. A player command other than `mode`, `sos` or `cease` switches an `auto` unit to `manual` (the AI would otherwise undo it). Events go through `sim.events` (all optional).

The director runs five phases on the sim clock (`PHASES`): Registration (0 s), the bombardment (330 s), the counter-attack with SOS (900 s), Night (1300 s), Zero hour with the creeping barrage the British infantry follow (1850 s). `sim.clock` is the hour of day as a time lapse (`CLOCK_KEYS`: 04:45 at 0, 06:12 at 330 s, 14:30 at 900 s, 19:30 at 1300 s, 05:06 next morning at 1850 s, 06:42 at 2300 s); a game is about 40 minutes of game time. Loss: two front sectors lost or every piece destroyed. Hostile signature (`unit.signature`, flash and sound ranging) builds with every round and German batteries walk counter-battery fire onto the loudest unit. The sim is deterministic per seed: take randomness from `sim.rng`, never `Math.random` (render-only code such as fx may use it). AI crews (`mode: 'auto'`) are tuned to be imperfect so the player matters: **after touching `GUNS`, `SHELLS`, `TARGETS`, `FFE`, `DIFFICULTY`, `PHASES`, the crew logic (`crews.js`), `enemy.js` or `director.js`, re-run `tools/simtest.mjs`**. Balance (DESIGN.md "Balance", seeds 1 to 72, the finished tree), games won out of 72 by the all-auto crews, the scripted 15-inch + 9.2-inch + 6-inch player and the scripted player on all five:

| Difficulty | all auto | scripted 15in+9.2in+6in | scripted all five |
|---|---|---|---|
| Easy | 39 | 66 | 69 |
| Normal | 14 | 48 | 61 |
| Hard | 0 | 4 | 15 |

(lead) Normal re-run on seeds 1 to 72 after the loading elevations were aligned with the models (`GUNS[kind].loadEl`); Easy and Hard are from before that change.

On Normal the auto crews hold the SOS 46 % of the time (scripted all five 77 %), and 50 % of the infantry reach the objective with auto crews against 68 % with the scripted player (the attack needs 60 % on Normal, 50 % Easy, 70 % Hard). Keep the all-auto crews losing most games and the scripted player winning most on Normal. Tuning knobs: `DIFFICULTY`, the dispersion and calibration in `GUNS`, the `SHELLS` radii, the counter-battery cadence in `enemy.js` (one round per gun per 85 s / (cb * activity)), the breach penalty in `director.js` (0.5 of a sector per group in), the AI delays in `crews.js`. Single games flip near the loss line, so decide on 72 seeds or more.

### Tutorials (`src/tutorial.js`)

Six lessons (`TUTORIALS`: basics, ranging, clockcode, heavy, counter, sos) on the scripted range (`sim.newGame({ scripted: true })`, `sim.script`; DESIGN.md "Tutorial (phase 3)"), run by the `Tutorials` class (the iads pattern: step `title/text/goal/hi/enter/tick/done/demo`, card `#tut-card`, list `#tut-menu`, progress in localStorage `drumfire.tutorials`). Console controls are tagged with `tut(el, name)` (`src/ui/highlight.js`) and pulsed by a step's `hi`. main.js owns the wiring: the `host` object (enter/leave, select, follow, scale), `unitKey` (a lesson only allows the units it lists), and the daylight rule: while a lesson runs `clockHour()` returns the sim clock clamped to 09:00 to 15:00 (never `?hour=` or the slider), the weather is forced to Clear (the gear menu may pick Overcast, anything else is put back) and the player's weather returns on leaving. `?tutorial=<id>` starts a lesson; Esc or Exit leaves to the title and the attract battle. Every step with a `done` also has a `demo(T)` that does it with the console's commands, so `__drumfire.tutorial.autoplaySync({ id, scale = 6 })` plays a whole lesson without drawing and returns `{ finished, simTime, steps: [{ id, sim, skipped }], stalled }` (a step that cannot finish within its `limit` sim seconds is skipped and listed in `stalled`); `autoplay()` does the same on the live loop and returns a promise. That is how the lessons are tested: run each id a few times (the seed is random) and expect no `stalled`. After changing a lesson, `GUNS`, the observers or `sim/script.js`, re-run them.

### Rendering

`render/index.js` `createRender({ scene, sim, terrain, fx, rigs, camera? })` returns `{ update(dt, rawDt, sim, fx, camera), reset(sim), select(unitId), onFire(unit, piece), onEnemyFire(src, part, shell), onBurst(pos, info), newestShell(unitId), eye(unitId, out) }`. `render/guns.js` poses the rigs from the sim (`models/guns.js` `buildGun(kind)`: pivots `traverse elevation recoil breech tray`, bl15 `crane` and `hoist`, rail `trolley`; anchors `eye muzzle breech tray shellStack crew`; call `rig.update?.(dt)` every frame): traverse and elevation from `piece.az/el`, recoil from `piece.firedAt`, the breech from the open and close steps, a wreck pose for a dead piece. The loading choreography (`render/crews.js`) is a pure function of `piece.job`, the time since `firedAt` and `piece.fireAt`, so time compression and `fastForward` are exact: the 15-inch crane lifts the shell and swings it onto the tray, the railway gun's trolley runs the round forward, the 9.2-inch pair carries it, the 6-inch and 60-pounder carriers bring it by arm; rammer, cordite bags, lanyard, everyone turning away and covering ears before a shot. Crew level of detail follows the camera and the selected unit. `render/shells.js` draws shells in flight as instanced meshes per kind, interpolated with `sim.alpha` and enlarged with distance. `render/targets.js` builds the sim's targets from `models/targets.js` (`setDamage` per sim part, battery guns recoil, the balloon falls burning, mobile targets only while `present`; the target root is turned by the render layer). Infantry (`models/infantry.js`, soldiers from `models/inf/`) are instanced, fall when `alive` drops and are thrown by nearby bursts. Models are procedural: guns in `models/v/`, rig helpers in `models/rig.js` and `kit.js`, German guns, the balloon, dumps, pillboxes and the railyard in `models/t/`, shells in `models/shells.js`. Part positions for sim targets come from `models/t/layout.js` (`partLayout`, Node-safe).

World dressing (`src/world/`): `buildWorld(scene, terrain)` builds trenches and sandbags, wire, gun pits and battery positions (`battery.js`, with `positionAnchors(unitId, pieceIndex)`), rails (`RAIL_MAIN`, `RAIL_SPUR`), roads and plank tracks, and the ruins of Ypres and the villages, in 256 m tiles around the camera inside a per-frame time budget, with coarse "far" groups; `world.invalidate(x, z, r)` rebuilds tiles near a new crater. `world/mats.js` exports `CUTAWAY` (uniforms `a` camera, `b` focus, `r` radius): camouflage scrim between the camera and the unit it orbits is not drawn, main sets it every frame (`r = 0` off, 7 while orbiting a unit). Terrain (`terrain.js`, a camera-centred CPU geometry clipmap over the pure `terrainHeight.js` `heightAt` that the sim also uses; `terrainField.js` the ground shader field) draws trenches, plank tracks and the old craters from `trenchlines.js` and the cellular pattern in `terrainHeight.js`; `craters.js` stamps runtime craters (`craters.add(x, z, radius, depth, { scorch, water })`, visual only) and `terrain.heightAt` includes them. `vegetation.js` and `grass.js` plant the trees and grass, `terrain.groundAt(x, z)` names the surface (mud, water, grass, road, concrete, rubble) for burst fx and sound.

### FX, post and flares

`fx.js` is the iads `FX` (smoke, glow, debris, shard pools, a fixed pool of 4 PointLights, `explosion`, `dust`, `fire`, `burnSite`, `fx.ground`) extended with the artillery set in `fx/artillery.js`: `gunBlast(p, dir, calibre, { night })` (fireball, flame tongue, cone of smoke and dust, ground dust ring, cordite cloud that drifts with the wind), `shellBurst(p, { calibre, fuze, ground, crater })` (earth geyser, clods on ballistic arcs, shockwave dust ring, water spout on water, brick dust on rubble), `shrapnel(p, calibre)` (airburst ball), `cookOff(p, size)` (ammunition dump or pit: fireball, mushroom, flying burning rounds, follow-up pops), plus `fx/clods.js`, `fx/emitters.js` (timed emitters in typed arrays), `fx/atlas.js` (the smoke puff atlas) and `fx/kinds.js`. Nothing may allocate per frame; budgets scale with `setBudget(q.fx)`. Brief analytic lights: `flares.js` owns up to `MAX_FLARE_LIGHTS = 16` lights (Very, SOS and star flares plus brief flashes), sorted each frame by closeness to the camera into `globalUniforms.uFlarePos/uFlareCol/uFlareRng/uFlareCount`; fx never touches the uniforms, it calls the hook `fx.onFlash(pos, color, intensity, life, opts)` which main wires to `flares.flash`. Other hooks: main wires `fx.onShock` to `post.shockwave(pos, { radius, speed, strength })` (screen-space refraction ring), `fx.onHeat` to `post.heat` (shimmer over a muzzle); `fx.onGust` (grass flattening in a muzzle wedge) exists but main does not wire it; `post.dazzle(k)` is the exposure kick for a blast near the camera. Every shader loop over the flare uniforms must use `MAX_FLARE_LIGHTS` and `flareAtt`.

Framework rules carried over from maxgfx and iads: `shaderlib.js` overrides three's fog/lighting chunks globally and `patchMaterial` needs a unique key per patch; materials created after `patchSceneFog` must patch themselves; never add or remove three.js lights at runtime (the fx pool is fixed and the hemisphere night light is added once); `noise.js` and `shaderlib.js` are identical in the sibling projects.

### UI (`src/ui/`) and audio (`src/audio.js`)

`new Panel(root, { audio, onSelect, onCommand })`, `panel.update(view)` with `view = { sim, selectedId, dt, time }` (also accepts the iads style `(dt, view)`), and the optional hooks `panel.radio(text, kind)`, `panel.sos(sectorId)`, `panel.reset()`, `panel.dispose()`. The panel reads only what is passed in and talks back through `onSelect(unitId)` and `onCommand(unitId, name, args)`; it watches `sim.shells` itself (a shell that vanishes has burst at its last position: fall of shot, numbered per unit, enemy bursts within 450 m of a piece drawn as red splashes) and reads reports from `sim.missions[].reports`. One console for every unit kind (`ui/consoles/console.js`, per-kind differences in `common.js` `KINDS`): the artillery board (`board.js`, a linen trench map with the grid, click lays the guns, click a target takes its mission, drag pans, wheel zooms), the fire order card, the range table, the guns card, the mission list and the message pad (`messages.js`, `tracker.js`). A control that the AI crew would undo first switches the unit to manual. The console owns Tab/Shift+Tab (mission cursor), Enter (take it), Space (fire), arrows (correct add/drop/left/right; Shift = 10 yards, else the step), X (step 10/25/50/100/200 yards), Q/E (charge), R (rounds), Z (fuze), A (auto/manual), S (SOS for the alarmed or weakest sector), Backspace/Delete (cease), `.` (apply the pencilled correction of the newest report). Main owns 1 to 5, C, F, M, H, F3, `[` and `]`. Corrections are in yards on the keys and converted to metres for `correct`. `ui.html` runs the panel against `src/ui/mock.js`, which must keep the shape of the sim.

`AudioEngine` renders its banks at `start()` (a user gesture), lays the recordings over them when decoded (the synthesized sounds play without them), routes world sounds with the 343 m/s travel delay, distance low-pass and air absorption, and runs shell flight voices with Doppler. API: `gun(pos, calibre)`, `burst(pos, calibre, { fuze, ground })`, `shell(shell)`, `incoming(shell)`, `cookOff(pos, size)`, `load(step, pos, kind)`, `flare(pos, kind)`, `ui(name)`, `setAmbience({ drumfire, rain, wind })`, `setVolume`, `toggleMute`, `deafen(k)`, `update(dt, camera)`, and the callback `audio.onShock = ({ d, k, pos }) => {}` that main uses to shake the camera and dazzle the post when a close blast's pressure wave arrives. Gun and burst classes by calibre (`classOf`): light < 4 in, field < 5.5, med < 7.5, heavy < 12, huge.

### Reference workflow

`refs/<group>/README.md` sheets (dimensions, profiles, feature checklists, photo index with licences) and `refs/<group>/photos/` (bl15in, bl92in, bl6in26cwt, bl60pdr, railway, german, battlefield, procedure) are local reference only: Wikimedia Commons photographs, gitignored, not part of the game. Model and world changes follow it: compare renders from `/models.html?kind=<kind>` with the photos from matching angles, check the `&ortho=` blueprint views against the dimension tables, and iterate with `tools/shot.mjs`. The guns are the stars: get silhouettes, proportions and the distinctive parts right. Conventions: 2-space indent, single quotes, semicolons, compact code, comments that explain why; no em dashes in prose or comments; never commit unless asked.
